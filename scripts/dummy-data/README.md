# Dummy data

Generated by `pnpm seed:dummy`. Regenerate any time — the script is
idempotent and skips what already exists.

```bash
pnpm seed:dummy              # write the CSV files and seed the database
pnpm seed:dummy --csv-only   # write the CSV files only
pnpm seed:dummy --no-csv     # seed the database only
```

It writes to whichever database the API's `.dev.vars` points at. In this
repository that is the live Supabase project, so **these are real accounts
on it** — 112 of them.

## The accounts

| Role | Count | Email | Password |
|---|---|---|---|
| Student | 100 | `a@student.matrix.com` … `cv@student.matrix.com` | `Matrix@2026` |
| Faculty | 10 | `a@faculty.matrix.com` … `j@faculty.matrix.com` | `Matrix@2026` |
| Admin | 2 | `a@admin.matrix.com`, `b@admin.matrix.com` | `Matrix@2026` |

The local part is letters only: `a` … `z`, then `aa` … `az`, `ba` … and so
on. `a@student.matrix.com` is Student A, roll number `23BCA001`.

Students carry a roll number (`23BCA001` … `23BCA100`) and an admission
year of 2023. Faculty carry an employee code (`EMP-F001` … `EMP-F010`) and
a department. Admins carry an employee code (`EMP-A001`, `EMP-A002`).

`ids.json` has the ids the app needs — batch, program, both semesters and
every course — so you can paste them into a form.

## What else it creates

- **Batch** BCA 2023 → **program** BCA → **semesters 1 and 2**
- **Courses**: CS101, CS102, MA101, EN101 in semester 1; CS201, CS202 in
  semester 2 — each with a `midterm` (50) and a `final` (100) exam type
- **Faculty assignments**: four, over the semester-1 courses
- **Enrollments**: all 100 students in semester 1
- **Attendance**: two sessions (2026-11-09, 2026-11-10) of CS101 for every
  student — about 70% present, 20% absent, 10% late
- **Marks**: a draft `midterm` for every student in CS101

## The CSV files

### `enroll-sem2.csv` — the bulk-enroll import

The format the admin **Enrollments** page's CSV upload takes: a
`roll_number` column, and any other columns are ignored by the parser.

Use it on **semester 2**, which the seeder leaves empty, so the import
reports all 100 enrolled. Semester 1 is already enrolled — uploading the
file there reports 100 `already_enrolled`.

### `enroll-sem2-with-errors.csv` — the error path

Five rows, four of which cannot work, so the error report has something to
report:

| Row | Roll number | What it exercises |
|---|---|---|
| 2 | `23BCA001` | a good row |
| 3 | `99ZZZ999` | `no_such_student` — nobody owns that roll number |
| 4 | *(blank)* | `validation_failed` |
| 5 | `23BCA002` | a good row |
| 6 | `23BCA001` | `already_enrolled` — a duplicate in the same file |

### `marks-cs101-midterm.csv` — the faculty marks upload

The format the faculty **marks entry** page's CSV upload takes:
`roll_number`, `exam_type`, `marks_obtained`. The values are in the range
4–49 against the `midterm`'s 50.

### `users.csv` — the account list

Every account with the fields the **Add user** form needs. There is no CSV
*import* for users — that flow is the form — so this is a reference table
and a starting point for one.

## Where it goes

- Attendance: sign in as a student, open **My Attendance**.
- Marks: sign in as a student, open **My Results**.
- The roster: sign in as faculty, open a course's **Roster**.
- The admin list: sign in as an admin, open **Users** — 122 accounts now.
